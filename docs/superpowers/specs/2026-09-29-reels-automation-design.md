## 1. 무엇을 만드는가

매물 사진 폴더와 대본 초안을 넣으면, 후킹하게 고친 대본에 TTS 나레이션과 자막을 얹어
**완성된 세로 영상**과 업로드용 텍스트 묶음을 만들고, **인스타그램 게시까지** 가는 도구.

**입력**
- 매물 사진 폴더 (jpg/png)
- 대본 초안 텍스트 — 사용자가 직접 씀

**출력** — 결과물 폴더 하나 + 게시된 릴스
- `output.mp4` — 세로 1080×1920, 나레이션 포함, BGM 없음
- `script_final.md` — 채택된 훅 + 최종 대본 + 탈락한 훅 후보와 탈락 이유
- `captions.md` — 제목 3안 + 캡션 + 해시태그
- `shotlist.md` — 자막 블록별 사진 배치표 (컷 길이, 켄번즈 방향)
- `check.md` — 자체 검수 결과 + 게시 결과(미디어 ID, 게시 시각)

## 2. 왜 만드는가

사용자는 마케터·기획자·PD로서 부동산 매물 릴스를 주 단위로 제작한다.
현재는 사진 확보 → 대본 초안 → 후킹 손질 → TTS 생성 → 사진 배치·자막 편집 →
BGM 추가 후 업로드의 6단계를 손으로 돈다.

**성공 기준은 단 하나 — 1건당 사용자 작업시간이 줄어드는 것.**
조회수나 시청유지율이 아니다. 시간이 안 줄면 실패다.

기준선(지금 1건에 몇 분 걸리는지)은 **아직 측정되지 않았다.** 1주차 첫 과제가 이 측정이다.
기준선이 없으면 성공 여부를 판정할 방법이 없다.

## 3. 영상의 형태

사람이 화면에 나오지 않는다. 사진·영상 소스 위에 자막과 TTS 나레이션이 올라간다.
이 형태이기 때문에 편집 프로그램을 사람이 만지지 않고 프로그램으로 직접 렌더링할 수 있다.

BGM은 사용자가 렌더링 결과물에 직접 붙인다. 파이프라인은 BGM을 다루지 않는다.

### 영상 길이

대본 분량이 길이를 정한다. 사용자가 쓰는 초안이 매 건 달라서 길이를 먼저 못 박으면
대본을 길이에 맞춰 깎아야 하고, 그건 후킹을 망친다.

**단 게시 API가 5~90초만 받으므로 이 범위는 하드 제약이다.**

| 구간 | 처리 |
|---|---|
| 5초 미만 | **중단.** 게시 불가. 대본 보강 필요 |
| 5~60초 | 통과 |
| 60~90초 | 경고 + 줄일 수 있는 구간 후보 제시. 자동으로 자르지 않음 |
| 90초 초과 | **중단.** 게시 불가. 어디를 줄일지 사용자가 결정 |

사진 장수와 컷 길이는 대본에서 역산한다 — 나레이션 타임스탬프가 자막 블록의 길이를
정하고, 자막 블록 수가 필요한 사진 장수를 정한다.

기술 규격(게시 API 요구): 9:16, H.264 또는 HEVC, MP4/MOV, moov atom 선두 배치,
오디오 AAC 48kHz 이하 1~2채널, progressive scan, closed GOP, 4:2:0 chroma subsampling.

## 4. 도구 선택

자동화 가능 여부를 가르는 기준은 하나다 — **API나 명령줄이 열려 있는가.**

| 도구 | 판정 | 이유 |
|---|---|---|
| **ffmpeg** | 채택 | 명령줄 영상 합성 엔진. 무료·오픈소스. 사진 배치·전환·자막·음원 합성을 명령으로 전부 처리 |
| **TTS API** | 채택 | 음성과 함께 **단어별 타임스탬프**를 주는 곳이어야 함. 이게 자막 싱크를 눈으로 맞추는 일을 없앤다 |
| **Instagram Content Publishing API** | 채택 | Reels 게시 공식 지원. 조건은 6절 참조 |
| **n8n** | 채택 (배관 한정) | 트리거·업로드·재시도·알림. 판단 로직은 넣지 않음 — 5절 참조 |
| 브루(Vrew)·캡컷 | 제외 | 화면만 있고 외부에서 조종할 창구가 없음. 화면 대리 클릭은 툴 업데이트마다 깨지고 약관 소지 |
| 프리미어 + 스크립트 | 제외 | 어도비 구독 필요, 스크립트 환경이 까다롭고 툴 업데이트마다 깨짐. 1인 운영에 유지비 과다 |

### TTS 선택 기준 (구현 시 결정)

필수 조건: ① 한국어 음성 ② **단어 단위 타임스탬프 제공** ③ 상업적 이용 허용.
후보군은 구글·애저·일레븐랩스·클로바보이스·타입캐스트 계열. 한국어 자연스러움은
국내 서비스 계열이 강한 편이다.

**가격과 약관은 수시로 바뀌므로 이 문서에 적지 않는다.** 키 발급 시점에 직접 확인한다.
키는 사용자가 직접 발급·결제하고, 도구는 발급된 키를 받아 쓰기만 한다.

## 5. 스택 — 왜 하이브리드인가

n8n은 **배관 도구**다. 실제 일은 노드 뒤의 API가 하고, ffmpeg도 n8n 안에서 호출된다.
자동화 가능 범위를 n8n이 넓혀주지는 않는다.

널리 돌아다니는 n8n 숏폼 완전자동화 사례는 구조가
`LLM 대본 → AI 이미지·영상 생성 → TTS → ffmpeg 합성 → 업로드`이고, **소재까지 AI가 만든다.**
그래서 사람 손이 0이 된다.

이 프로젝트는 **실제 매물 사진**을 써야 한다. 그 사진이 상품 자체라 AI 생성으로 대체할 수
없고, 그래서 "어느 사진을 어느 문장에 붙이나"라는 판단이 남는다. 그 사례가 완전 무인인 것은
도구가 뛰어나서가 아니라 판단할 게 없어서다.

| 영역 | 담당 | 이유 |
|---|---|---|
| 대본 후킹 업그레이드, 개인정보 점검, 사진 배치 판단, 검수 | **코드** | 판단 로직. n8n 코드 노드에 넣어도 결과가 같고 테스트가 어려워진다 |
| 트리거(폴더 감지·스케줄), 업로드 호출, 실패 재시도, 완료 알림 | **n8n** | n8n이 실제로 잘하는 것. 재시도·대기·분기가 공짜로 따라온다 |

코드 쪽은 CLI로 실행 가능하게 만든다. 그러면 n8n은 Execute Command 노드 하나로 붙고,
n8n을 쓰지 않아도 손으로 돌아간다. **엔진이 n8n에 묶이지 않는 게 핵심이다.**

## 6. 파이프라인 — 10단계

| # | 단계 | 하는 일 | 개입 |
|---|---|---|---|
| 1 | **입력 수집** | 사진 폴더 경로 + 대본 초안 읽기. 사진 해상도·비율 확인 | 무인 |
| 2 | **개인 식별 요소 점검** | 사진 전수 확인 — 얼굴, 차량 번호판, 문패, 우편물의 이름·주소, 액자 속 가족사진, 창밖 옆집. 의심 컷을 목록으로 제시 | **승인 필수 (항상)** |
| 3 | **대본 후킹 업그레이드** | 훅 3안 생성 → 1안 채택(탈락 이유 기록) / 결론 유보 배치 / 클라이맥스 후치 / **공유 장치 삽입** / 대본 분량으로 예상 초수 산출 | 무인 |
| 4 | **자막 분할** | 화면 자막 단위로 쪼개고 강조어 지정 | 무인 |
| 5 | **TTS 생성** | 음성 파일 + 단어별 타임스탬프 | 무인 |
| 6 | **사진 배치안** | 자막 블록별 사진 매칭 + 컷 길이 변주 + 켄번즈 방향을 표로 제시 | **초기 3건 승인, 이후 무인** |
| 7 | **렌더링** | ffmpeg 합성 | 무인 |
| 8 | **검수** | 길이(5초 미만·90초 초과는 중단), 자막 화면 넘침, 싱크 오차, 첫 프레임 훅 텍스트, 게시 규격 적합성 | 무인 |
| 9 | **결과물 저장** | 폴더 하나에 mp4 + 텍스트 묶음 전부 | 무인 |
| 10 | **게시** | 공개 URL 업로드 → 컨테이너 생성 → 상태 폴링 → 게시 → 공개 URL 즉시 삭제 | **승인 기본 유지** |

### 2단계를 빼지 않는 이유

매물 사진에는 거주자 얼굴, 차량 번호판, 우편물의 이름·주소, 액자 속 가족사진,
창밖으로 보이는 옆집 문패가 섞여 들어온다. 자동화가 사진을 그대로 영상에 박으면
이걸 놓친다. 한 번 게시되면 회수가 불가능하다.

**이 단계는 초기 3건이 지나도 승인을 유지한다.** 6단계와 달리 학습으로 줄일 수 없다 —
틀렸을 때의 대가가 재렌더링이 아니라 타인의 개인정보 유출이다.

### 6단계 승인을 3건 후 줄이는 방식

1~3건은 배치표를 사람이 확인하고, 사용자가 고친 배치를 전부 기록한다.
그 수정 패턴을 배치 규칙으로 흡수한 뒤 4건째부터 무인으로 돌린다.
무인 전환 후에도 배치표는 결과물 폴더에 남으므로 사후 확인은 가능하다.

### 10단계 게시 — 조건과 제약

**계정 조건** — 인스타그램 비즈니스 또는 크리에이터 계정 + 페이스북 페이지 연결.

**권한** — `instagram_business_basic`, `instagram_business_content_publish`.
각 권한은 **Meta 앱 심사를 따로 거쳐야 하고**, 전체 사용자 플로우를 담은 스크린캐스트를
제출해야 하며 **2~4주가 걸린다.**

**게시 흐름** — `POST /{ig-user-id}/media`(media_type=REELS, 공개 video_url) →
`GET /{container-id}?fields=status_code` 폴링해 FINISHED 대기 → `POST /{ig-user-id}/media_publish`.

**공개 URL 호스팅이 필요하다.** Meta가 영상을 직접 가져가는 방식이라 파일이 공개 주소에
올라가 있어야 한다. 게시가 끝나면 **즉시 삭제한다.** 영상이 공개 주소에 노출되는 시간을
최소화하는 것이 2단계 개인정보 점검의 실효성을 지킨다.

**게시 전 승인을 기본으로 둔다.** 게시는 되돌릴 수 없는 외부 공개 행위다.
운영이 안정되면 해제할 수 있게 설정으로 빼되, 기본값은 승인이다.

## 7. 시청유지와 도달을 만드는 요소 — 템플릿에 규칙으로 박는 것

공식 확인된 랭킹 신호(8절)에 직접 대응시킨다. 아래는 전부 ffmpeg·대본 단계에서
구현 가능하며 매 건 자동 적용된다.

### Watch time 축 (시청시간·재생 반복률)

1. **3초 훅** — 첫 프레임 큰 텍스트 + 나레이션 첫 문장이 동시에 때림
2. **결론 유보** — 가격·평수·반전 정보를 앞에서 까지 않고 뒤에 배치
3. **진행 카운터** — `1/5`, `2/5` 를 화면 구석에 표시해 남은 분량을 보이게
4. **컷 리듬 변주** — 균일한 2.5초가 아니라 1.2~4초로 흔든다. 균일한 리듬이 이탈을 만든다
5. **단어 단위 자막 강조** — 핵심어만 색이 팝. TTS 타임스탬프가 있어 정확히 맞는다
6. **클라이맥스 사진 후치** — 가장 좋은 컷을 마지막에
7. **루프 엔딩** — 마지막 프레임이 첫 프레임으로 이어져 자연 반복. **재생 반복률에 직접 걸린다**

### Sends 축 (DM 공유율) — v1에 빠져 있던 부분

공유는 비팔로워 도달의 최강 신호인데, v1의 7요소는 전부 시청시간 지향이라
**공유를 유발하는 장치가 하나도 없었다.** 부동산은 "이 조건이면 누구한테 보내줄 만하다"가
명확한 소재라 구조화하기 쉽다.

8. **조건 명시** — 평수·보증금·월세·역세권·입주가능일을 자막에 숫자로 박는다.
   "누가 이걸 찾고 있는지"가 특정되면 그 사람에게 전달된다
9. **비교 기준 제시** — 같은 가격대·같은 동네 대비 무엇이 다른지 한 줄.
   받는 사람이 판단할 재료가 있어야 보낸다
10. **전달 대상 호명** — "전세 알아보는 사람", "신혼집 보는 중이면" 같이 받을 사람을 지목
11. **공유 CTA 후치** — 마지막 자막에 저장·공유 유도. 앞에 두면 시청을 끊는다

### Likes 축

좋아요는 기존 팔로워 대상에서 더 무겁게 걸린다. 별도 장치를 두지 않고
위 요소의 결과로 따라오는 것으로 본다. 억지 유도는 넣지 않는다.

비주얼 수준은 **단순 전환 + 켄번즈(사진 천천히 확대) + 자막 애니메이션**이다.
화려한 모션그래픽은 범위 밖이고, 도달 신호에 직접 걸리는 요소도 아니다.

## 8. 템플릿의 근거를 어디서 가져오는가

### 1차 근거 — 공식 확인된 랭킹 신호

인스타그램 책임자 Adam Mosseri가 공개적으로 밝힌 신호다. 추측이 아니므로 템플릿의
기준으로 쓴다.

| 신호 | 내용 | 비중 |
|---|---|---|
| **Watch time** | 총 시청시간 + 재생 반복률 | 가장 강력. 특히 신규 노출 |
| **Sends per reach** | DM 공유율 | 비팔로워 도달의 최강 신호. 좋아요의 3~5배 가중 |
| **Likes per reach** | 좋아요율 | 기존 팔로워 대상에서 더 무겁게 |

주의 — 공개된 것은 **무엇이 측정되는가**이고 **무엇을 만들면 되는가**는 아니다.
신호에서 제작 규칙을 끌어내는 것은 추론이다. 7절의 11개 요소가 그 추론이고,
30일간 자체 성적으로 검증·수정한다.

### 배제하는 것 — 출처 없는 꿀팁

"최적 길이는 몇 초", "해시태그는 몇 개", "몇 시에 올려라" 같은 수치는 블로그·영상마다
다르고 근거가 제시되지 않는다. **템플릿에 박지 않는다.** 한 번 박히면 30일 내내 따라다닌다.

### 보조 근거

1. **잘 된 타사 부동산 릴스 분석** — 제3자 콘텐츠를 보고 구조를 배우는 것은 권한 문제가 없다
2. **사용자 판단 기준의 문서화** — 인터뷰로 뽑는다
3. **30일간 쌓이는 자체 성적** — 게시를 자동화하면 인사이트 수집도 같은 API로 가능해진다.
   이것이 최종 근거가 된다

템플릿은 30일 끝에 확정되는 문서가 아니라 30일 내내 갱신되는 살아있는 문서다.

## 9. 구성 요소

각 요소는 독립적으로 테스트 가능해야 한다.

| 요소 | 책임 | 의존 |
|---|---|---|
| **입력 로더** | 사진 폴더와 대본 초안을 읽어 내부 형식으로 정규화 | 없음 |
| **개인정보 스캐너** | 사진에서 개인 식별 요소 의심 컷을 골라 목록화 | 입력 로더 |
| **대본 빌더** | 초안 → 훅 후보 → 채택 → 구조 재배치 → 공유 장치 삽입 → 자막 블록 분할 | 템플릿 문서 |
| **TTS 클라이언트** | 자막 블록 → 음성 파일 + 단어별 타임스탬프 | 외부 API |
| **배치 플래너** | 자막 블록 + 사진 목록 → 배치표(사진, 컷 길이, 켄번즈 방향) | 대본 빌더, 입력 로더 |
| **렌더러** | 배치표 + 음성 + 자막 → mp4 | ffmpeg |
| **검수기** | mp4 + 배치표 → 검수 결과 + 게시 규격 판정 | 렌더러 |
| **파생 텍스트 생성기** | 최종 대본 → 제목 3안 + 캡션 + 해시태그 | 대본 빌더 |
| **호스팅 클라이언트** | mp4 → 공개 URL, 게시 후 삭제 | 외부 스토리지 |
| **게시 클라이언트** | 공개 URL + 캡션 → 컨테이너 생성·폴링·게시 | Instagram API, 호스팅 클라이언트 |
| **CLI** | 위 요소를 순서대로 실행. n8n이 붙는 지점 | 전부 |

**경계 원칙** — 렌더러는 대본을 모르고 배치표만 안다. 대본 빌더는 ffmpeg를 모른다.
게시 클라이언트는 영상이 어떻게 만들어졌는지 모르고 파일과 캡션만 안다.
이렇게 두면 템플릿을 고쳐도 렌더러를 건드릴 필요가 없고, 게시 방식이 바뀌어도
제작 로직이 안 깨진다.

## 10. 오류 처리

| 상황 | 처리 |
|---|---|
| 사진 장수가 자막 블록보다 적음 | 중단하고 부족한 장수를 알림. 사진을 복제해 때우지 않는다 |
| TTS API 실패·한도 초과 | 중단하고 원문 오류를 그대로 보여줌. 재시도는 사용자가 결정 |
| ffmpeg 미설치 | 첫 실행 시 확인하고 설치 안내 후 중단 |
| 자막이 화면을 넘침 | 검수에서 경고. 자동으로 글자를 줄이지 않는다 |
| 대본이 5초 미만 / 90초 초과 | **중단.** 게시 규격 위반. 자동으로 자르거나 늘리지 않는다 |
| 60~90초 | 경고 + 줄일 수 있는 구간 후보 제시 |
| 개인정보 의심 컷 발견 | 해당 컷을 제외한 채 진행할지, 사진을 교체할지 사용자가 선택 |
| 앱 심사 미승인 상태에서 게시 시도 | 9단계까지만 돌고 "심사 대기 중"으로 중단. mp4는 남는다 |
| 게시 컨테이너가 ERROR 반환 | Meta가 준 오류 코드·메시지를 그대로 보여줌. 규격 문제면 어느 항목인지 지목 |
| 폴링 타임아웃 | 공개 URL을 삭제하지 않고 보류. 중복 게시를 막기 위해 자동 재시도하지 않는다 |
| 게시 성공 후 공개 URL 삭제 실패 | **경고로 끝내지 않고 재시도.** 끝까지 실패하면 수동 삭제 대상으로 명시 |

공통 원칙 — **자동으로 때우지 않는다.** 품질 판단이 필요한 실패는 전부 사람에게 넘긴다.
말없이 보정하면 결과물이 왜 이상한지 추적할 수 없다.

게시 관련 추가 원칙 — **중복 게시보다 미게시가 낫다.** 애매하면 멈춘다.

## 11. 테스트 방침

- **대본 빌더** — 초안 고정 입력 → 훅 후보 개수, 공유 장치 삽입, 자막 블록 분할, 강조어 지정
- **배치 플래너** — 자막 블록 N개 + 사진 M장 조합에서 컷 길이 합이 나레이션 길이와 일치하는지
- **렌더러** — 짧은 더미 입력(사진 2장 + 3초 음성)으로 mp4가 나오고 해상도·길이가 맞는지
- **검수기** — 의도적으로 깨뜨린 입력(자막 초과, 4초, 95초)에서 중단·경고가 갈리는지
- **TTS 클라이언트** — 실제 API를 때리지 않고 기록된 응답으로 타임스탬프 파싱을 검증
- **게시 클라이언트** — 기록된 응답으로 컨테이너 폴링 상태 전이(IN_PROGRESS→FINISHED, →ERROR)와
  타임아웃 처리를 검증. **실계정 게시는 테스트에 포함하지 않는다**

## 12. 범위 밖 — 제외 확정

| 제외 항목 | 이유 |
|---|---|
| 유료 스톡·BGM 구매·다운로드 | **결제** 발생 |
| BGM 합성 | 사용자가 결과물에 직접 붙임 |
| 브루·캡컷 GUI 대리 조작 | 남의 프로그램 조종. 업데이트마다 깨지고 약관 소지 |
| 실사 컷편집 (사람이 나오는 영상) | 컷 판단이 매 클립 달라 순서로 고정되지 않음 |
| AI 생성 이미지·영상으로 소재 대체 | 매물 실사가 상품 자체. 대체 불가 |
| 출연자·인터뷰이 섭외 | **개인정보** 취급 |
| 화려한 모션그래픽 | ffmpeg 범위 밖이고 도달 신호에 직접 걸리지 않음 |
| 댓글 자동 응답·DM 자동 발송 | 타인과의 상호작용. 정책 리스크 + 개인정보 |
| 팔로우·좋아요 자동화 | 플랫폼 정책 위반 |

## 13. 30일 진행 계획

| 주차 | 할 일 | 판정 |
|---|---|---|
| **1주차** | **기준선 측정 — 지금 1건에 몇 분** / ffmpeg 설치 / TTS 선택·키 발급 / **비즈니스 계정 전환 + FB 페이지 연결 + Meta 앱 생성·심사 제출** / 타사 릴스 분석해 훅 유형표·템플릿 v1 | 기준선 숫자가 나왔는가, 심사가 제출됐는가 |
| **2주차** | 1~9단계 구현, 실제 1건 완주(게시는 손으로). **사용자가 손댄 부분 전부 기록** | 1건이 mp4까지 돌았는가 |
| **3주차** | 손댄 부분을 규칙으로 흡수해 템플릿 v2 → 3건 돌려 수정량 감소 확인. 6단계 무인 전환 판단. 심사 통과 시 10단계 붙임 | 수정량이 줄었는가 |
| **4주차** | 1건당 시간 재측정해 기준선과 비교. 자체 성적(시청시간·공유) 들어오면 템플릿 v3 | **시간이 줄었는가 — 최종 판정** |

심사는 기다리는 일이라 1주차에 제출해두고 본론에 집중한다. **심사가 30일 안에 끝나지
않더라도 2~9단계는 독립적으로 완성된다** — 게시 자동화는 마지막에 붙는 한 단계일 뿐이다.

## 14. 사용자가 준비할 것

1. **TTS API 키** — 한국어 + 단어별 타임스탬프 제공하는 곳. 후보 비교표가 필요하면 별도 정리
2. **사진 폴더 예시 1건** — 실제 매물 사진 세트
3. **대본 초안 예시 1건** — 지금 쓰는 그대로
4. **기준선 시간** — 다음 릴스 제작 시 단계별 소요 시간 측정
5. **인스타 비즈니스/크리에이터 계정 전환 + 페이스북 페이지 연결**
6. **Meta 개발자 계정** — 앱 생성과 심사 제출에 필요
7. **공개 호스팅** — 게시용 임시 공개 URL. 스토리지 선택은 구현 시 결정

## 15. 이후 로드맵 (30일 밖)

→ 3번: 자료·영상 소스 서치
